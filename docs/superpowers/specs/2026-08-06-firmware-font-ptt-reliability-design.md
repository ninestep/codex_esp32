# 固件中文与 PTT 可靠性修复设计

## 目标

修复 ESP32 界面中文缺字，以及真机按住 GPIO18 后豆包语音快捷键不触发、无音频输入的问题。设置页快捷键测试行为保持不变。

## 设计

### 中文字体

不再把 LVGL 示例 CJK 字体当作业务字库。使用仓内 `SourceHanSansSC-Normal.otf` 生成项目自有的 16px、4bpp 字体，字符集由固件 UI 的实际中文和 ASCII 组成。UI 统一引用该字体；主机测试解析 UI 字符串并验证生成字体声明覆盖所有非 ASCII 字符。

### ESP32 音频

音频硬件和采集任务在显示初始化前启动，避免显示/LVGL 消耗内部 SRAM 后才创建音频任务。由于板级音频与显示共用 I²C 总线，音频入口必须在初始化 I²S 和 codec 前显式建立 I²C bus，不能依赖显示初始化的副作用。每个可能失败的初始化步骤记录剩余内部堆和最大连续块。只有预录准备成功才允许发送 `PTT_BEGIN`；提交失败时立即发送 `PTT_END` 并恢复非 PTT 状态，禁止伪成功。

### Mac 音频路由

先把系统默认输入切换到 BlackHole，待系统级设备变更完成后，再把 AVAudioEngine 输出 AudioUnit 绑定到 BlackHole、读取设备原生输出格式并显式连接主混音器到输出节点，避免切换默认输入触发引擎重配并把输出跳回物理设备。16kHz 单声道播放节点仍由 AVAudioEngine 转换到 BlackHole 的原生格式。CoreAudio 属性设置和引擎启动失败时保留 OSStatus 或底层错误描述，便于现场日志定位；快捷键仍只在默认输入切换和引擎启动均成功后发送。

## 验证

- 主机测试：字体覆盖、固件音频初始化顺序、PTT 错误门禁。
- Swift 测试：BlackHole 使用绑定后的原生输出格式，既有快捷键恢复测试不回归。
- 构建：全新 ESP-IDF 构建和 macOS release app 构建。
- 真机：烧录后串口确认麦克风初始化成功；按住 GPIO18 时确认 Mac 音频引擎启动、豆包快捷键触发并收到连续音频帧；屏幕逐页检查中文。
