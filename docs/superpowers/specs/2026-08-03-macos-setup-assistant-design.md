# macOS 安装检查与一键配置设计

日期：2026-08-03
状态：设计已确认，待实施计划
关联设计：`docs/superpowers/specs/2026-08-02-codex-remote-control-design.md`

## 1. 摘要

Codex Remote Mac 客户端新增首次启动向导和长期可用的“安装与诊断”页面。客户端统一检查应用安装、Ghostty、Codex CLI、命令桥接、Codex hooks、BlackHole、macOS 权限、豆包快捷键和 ESP32 连接状态，并在用户授权后自动完成可安全处理的配置。

“一键配置”是一条可暂停、可继续、可复查的编排流程。它不会收集管理员密码，不绕过 macOS 权限或 Codex hooks 信任机制。涉及外部安装和用户配置写入时，界面先展示变更内容，再等待用户确认。

## 2. 目标与非目标

### 2.1 目标

- 首次运行时检查设备到位前的全部 Mac 侧准备项。
- 用一个入口完成可自动化的安装和配置，降低命令行操作量。
- 为每个检查项显示真实状态、失败原因、修复操作和脱敏日志。
- 支持单项修复、全部配置、重新检查和受控恢复。
- 允许用户直接输入豆包语音快捷键，并测试 macOS 是否成功发送按键事件。
- 保留平台适配边界，为 Windows 客户端复用检查结果模型和配置流程。

### 2.2 非目标

- 不自动安装 Homebrew。
- 不修改豆包输入法内部配置。
- 不绕过 macOS 蓝牙、麦克风或辅助功能授权。
- 不代替用户完成 Codex `/hooks` 信任确认。
- 不把“按键已发送”解释为“豆包已完成语音识别”。
- 不修改 BLE v1 协议、本地 IPC 契约或设备固件协议。
- 不在本阶段实现 Windows 客户端。

## 3. 用户流程

### 3.1 首次启动

客户端启动后执行只读检查。任一必需项未就绪时，客户端打开配置向导；全部就绪时进入主界面。用户可以选择“稍后设置”，但主界面持续显示未就绪提示，依赖缺失的功能保持禁用。

向导包含四个阶段：

1. 基础环境：应用位置、Ghostty 和 Codex CLI。
2. 自动配置：命令桥接、PATH、Codex hooks、BlackHole、系统权限和豆包快捷键。
3. 功能测试：会话发现、Ghostty 聚焦、滚动、Enter/Esc、快捷键、音频和 BLE。
4. 完成：展示运行状态和剩余的真机验收项。

### 3.2 一键配置

“开始自动配置”按依赖顺序执行：

1. 检查 Ghostty、Codex CLI 和客户端安装位置。
2. 安装 Codex Remote 命令桥接并配置 PATH。
3. 合并 Codex hooks。
4. 等待用户在 Codex `/hooks` 中确认信任。
5. 经二次确认后，通过 Homebrew 安装 BlackHole 2ch。
6. 引导用户授予蓝牙、麦克风和辅助功能权限，并在返回应用后复查。
7. 保存并测试用户输入的豆包语音快捷键。
8. 执行 Mac 侧综合测试；ESP32 未连接时把真机项目标记为“等待设备”，不判定失败。

流程在用户授权、外部安装或人工确认处暂停。应用退出或重启后重新读取真实环境，并从尚未就绪的步骤继续，不依赖上次缓存推断状态。

### 3.3 长期诊断

设置页新增“安装与诊断”分区，并保留现有 BLE、Socket、音频和快捷键设置。该分区提供：

- 重新检查全部项目；
- 修复单个项目；
- 再次运行自动配置；
- 查看当前步骤的脱敏日志；
- 恢复 Codex Remote 管理的配置。

安装日志与普通设置分开显示，避免状态信息淹没常用选项。

## 4. 状态模型

每个配置项使用统一状态：

| 状态 | 含义 |
|---|---|
| `checking` | 正在执行只读检查 |
| `ready` | 当前环境满足要求 |
| `needsConfiguration` | 已发现缺失或错误配置 |
| `waitingForUser` | 等待授权、确认或外部操作 |
| `configuring` | 正在执行已授权操作 |
| `failed` | 操作失败，附带明确原因 |
| `notApplicable` | 当前平台或安装方式不需要此项 |

每项结果包含稳定标识、状态、摘要、详细原因、可执行操作、检查时间和脱敏诊断信息。界面只在所有必需项为 `ready` 或 `notApplicable` 时显示“Mac 已准备就绪”。ESP32 真机测试使用独立的“等待设备/已通过/失败”结果，不影响设备尚未到位时的 Mac 配置完成度。

## 5. 架构

### 5.1 组件

```text
SetupAssistantView / InstallationDiagnosticsView
                     │
                     ▼
             SetupCoordinator
              │             │
              ▼             ▼
       SetupInspector   SetupExecutor
              │             │
              └──────┬──────┘
                     ▼
              PlatformSetupAdapter
                 ├─ macOS adapter
                 └─ Windows adapter（后续）
```

- `SetupInspector` 只读检查环境，不修改文件或系统状态。
- `SetupExecutor` 执行用户已确认的配置项，并逐步报告进度。
- `SetupCoordinator` 维护依赖顺序、暂停点和界面状态，不直接调用 shell 或系统 API。
- `PlatformSetupAdapter` 隔离 macOS 专属路径、权限、进程和输入事件。

检查结果模型保持平台无关。Ghostty、AppleScript、CoreAudio、CoreBluetooth、CGEvent 和具体文件路径不得进入共享 BLE 协议或设备端模型。

### 5.2 检查项

首版至少包含：

1. 客户端是否从稳定安装目录运行。
2. Ghostty 是否已安装且版本可识别。
3. Codex CLI 是否存在且版本可识别。
4. Codex Remote shim 是否存在并优先于真实 Codex。
5. PATH 管理区块是否正确且无重复。
6. Codex hooks 是否包含当前版本所需配置。
7. BlackHole 2ch 是否存在并可被 CoreAudio 识别。
8. 蓝牙、麦克风和辅助功能权限状态。
9. 豆包快捷键是否可解析并已完成发送测试。
10. 本地 IPC 服务和 Mac 客户端内部协调器是否可用。
11. ESP32 是否连接、BLE 协议是否兼容。

## 6. 配置执行细节

### 6.1 应用安装位置

客户端检测自身是否从稳定安装目录运行。若当前位于构建产物或临时目录，向导提供“安装到应用程序”。用户确认后，客户端复制应用、校验目标产物并从新位置重启。复制失败时保留当前应用和目标原状态。

### 6.2 Codex 命令桥接与 PATH

客户端在 Codex Remote 专用目录中建立 `codex` shim，不替换真实 Codex 文件。shell 配置使用带起止标记的托管区块，确保专用目录排在真实 Codex 之前。

写入前保存备份，写入后重新解析并验证生效顺序。重复执行只更新同一托管区块，不追加重复内容。恢复操作只删除该托管区块和专用 shim。

### 6.3 Codex hooks

客户端解析现有 `~/.codex/hooks.json`，合并 Codex Remote 使用的 `SessionStart`、`UserPromptSubmit`、`PermissionRequest` 和 `Stop` hook。合并过程保留其他工具和用户已有的 hook。

写入流程为：校验 JSON、生成备份、写入同目录临时文件、设置 `0600` 权限、原子替换、重新读取校验。输入文件非法或任一步失败时停止，不覆盖原文件。

客户端不伪造 hooks 信任状态。写入完成后，向导要求用户在 Codex 中运行 `/hooks` 并确认信任；随后通过真实 hook 事件和本地 IPC 验证链路。

### 6.4 BlackHole 2ch

检查器通过 CoreAudio 设备目录确认 BlackHole 2ch，不只判断 Homebrew 安装记录。

缺失时，向导先确认 Homebrew 是否可用。用户二次确认后，客户端执行官方 `brew install --cask blackhole-2ch` 并实时显示脱敏日志。系统没有 Homebrew 时，向导提供官方安装说明，不自动安装 Homebrew。

BlackHole 卸载独立于普通恢复操作，必须再次确认，以免删除其他应用正在使用的音频设备。

### 6.5 macOS 权限

客户端使用系统接口请求蓝牙、麦克风和辅助功能权限。系统设置打开后，向导进入 `waitingForUser`；用户返回应用时重新读取授权状态。

拒绝授权不会被记录为成功。辅助功能缺失时，Ghostty 聚焦、滚动、Enter/Esc 和豆包快捷键测试保持禁用，并显示受影响能力。

### 6.6 豆包语音快捷键

设置页提供文本输入框，支持用户直接输入 `⌥ Space`、`⌘ ⇧ V` 等组合。解析器将输入标准化，并拒绝缺少修饰键、未知键名或仅包含修饰键的组合。

“测试”按钮执行以下步骤：

1. 检查辅助功能权限和快捷键格式。
2. 显示三秒倒计时，让用户把焦点切到目标应用。
3. 使用 macOS 输入事件发送一次完整的 key-down/key-up 序列。
4. 报告“按键事件已发送”或明确失败原因。

测试结果不判断豆包是否弹出或完成识别。客户端不读取或修改豆包私有配置。

正式语音仍要求设备端先进入有效 Codex 会话。进入详情时，Mac 先聚焦对应 Ghostty terminal；用户按住实体键开始语音，松开结束。设备未进入会话时，Mac 拒绝 PTT。

## 7. 错误处理、日志与恢复

每一步返回结构化错误，不以 fallback 或模拟结果继续。错误至少区分：依赖缺失、权限拒绝、配置冲突、文件格式错误、命令退出失败、超时和验证失败。

诊断日志记录步骤、开始时间、退出状态和必要上下文；日志隐藏用户目录中的敏感片段、环境变量、token、完整命令输出中的凭证和录音内容。

配置文件修改采用备份和原子替换。恢复操作只处理 Codex Remote 创建或标记的内容：

- 删除专用 shim；
- 删除 PATH 托管区块；
- 删除 Codex Remote 自己的 hooks；
- 保留其他用户配置；
- 单独处理 BlackHole 卸载。

## 8. 界面设计

首次启动向导采用已确认的双栏结构：左侧显示四个阶段，右侧显示整体进度和检查清单。每个条目包含状态图标、标题、简短说明和当前可用操作。

颜色只辅助表达状态：绿色表示已就绪，琥珀色表示等待配置或确认，红色表示失败，灰色表示尚未检查或等待设备。图标和文字必须同时存在。

关键文案遵循以下规则：

- “已就绪”只表示检查证据满足要求。
- “按键事件已发送”不写成“豆包测试成功”。
- “等待设备”不写成“连接失败”。
- “配置失败”必须附带原因和下一步。

## 9. 测试与验收

### 9.1 自动测试

- 检查器：覆盖已安装、未安装、版本不可识别、配置损坏和权限不足。
- PATH：覆盖首次写入、重复执行、已有托管区块、备份、恢复和写入失败。
- hooks：覆盖空配置、保留第三方 hook、重复合并、非法 JSON、权限和原子替换失败。
- BlackHole：覆盖设备存在、Homebrew 可用、Homebrew 缺失、安装成功和命令失败。
- 快捷键：覆盖合法组合、非法输入、权限缺失、倒计时取消和事件发送失败。
- 编排器：覆盖自动推进、人工暂停、应用重启后复查、单项失败和恢复。

PATH、hooks 和 shim 操作必须通过幂等测试：连续执行多次不得产生重复内容或改变无关配置。

### 9.2 Mac 现场 smoke

在执行任何真实用户配置修改前单独取得授权。现场 smoke 检查：

1. 首次启动正确识别未就绪项目。
2. 自动配置在授权节点暂停，并在用户完成操作后继续。
3. Ghostty 会话可经 shim 和 hooks 建立映射。
4. 客户端可聚焦目标 terminal，发送滚动、Enter 和 Esc。
5. BlackHole 可接收设备音频，豆包快捷键可被发送。

### 9.3 真机验收

ESP32 到位后补充 BLE、音频流、实体键、触摸、屏幕状态和断线重连的端到端证据。在真机完成前，文档和界面不得声称这些项目已通过。

## 10. Windows 扩展

未来 Windows 客户端复用检查结果、步骤编排、BLE 协议、本地 IPC 契约和会话状态模型，并替换平台适配器：

- Ghostty 控制替换为 Windows Terminal、ConPTY 或目标终端适配器；
- CoreAudio/BlackHole 替换为 WASAPI 和选定的虚拟音频设备；
- AppleScript/CGEvent 替换为 UI Automation 和 Win32 输入 API；
- macOS 权限检查替换为 Windows 对应权限和安装状态检查。

共享模型不包含 Ghostty terminal ID、AppleScript 对象、CoreAudio UID 或 macOS 文件路径。Windows 实施前再确认虚拟音频依赖和终端控制方案，不在本阶段预装抽象实现。

## 11. 完成标准

- 首次启动向导和“安装与诊断”页面使用同一套真实检查结果。
- 一键配置可以暂停、继续、重试和复查。
- 客户端只在用户确认后修改 PATH、hooks 或安装 BlackHole。
- 豆包快捷键支持直接输入、格式校验、保存和按键发送测试。
- 所有自动配置操作幂等，并能恢复 Codex Remote 管理的内容。
- 缺失依赖、拒绝权限和外部命令失败均显示真实错误。
- Mac 定向测试和构建通过；真机项目与 Mac 配置状态分开报告。
